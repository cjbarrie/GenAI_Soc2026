# Take-home midterm specification

**Release:** after Session 6, October 7.  
**Due:** before Session 7, October 21.  
**Intended work:** approximately 4–6 hours.  
**Weight:** 20%, followed by a separate 5% oral walkthrough.

## Products

Submit one short notebook and one research-design memo.

1. **Trace and interpret:** predict and explain short programs using lists, dictionaries, conditionals, loops, and one function.
2. **Repair:** complete limited missing code in an annotation or treatment workflow. Students are never asked to write an entire API workflow from memory.
3. **Diagnose:** state the inferential target, identify patterned failure modes, and propose validation evidence for a flawed LLM-assisted study.
4. **Reconstruct:** create the model/settings/data/provenance record needed to interpret one result.

Every code response is annotated with input, type, operation, output, and research meaning. Package-method recall and transformer architecture are not assessed.

## AI use

The course policy applies: assistance is permitted with disclosure, but the student remains responsible for every line and claim. The subsequent oral walkthrough samples code from the submission and verifies independent understanding without live AI.

## Marking dimensions

- accurate tracing and output prediction;
- small, readable repair that satisfies the stated checks;
- match between inference and validation design;
- recognition of patterned rather than merely aggregate error;
- complete and interpretable reproducibility record;
- disclosure and evidence of checking.
