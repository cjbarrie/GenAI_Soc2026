## Substantive question

What kind of research technology is an LLM?

## Learning objectives

By the end, students should be able to:

1. state the inferential target: describe one model-assisted operation without mistaking its output for evidence.
2. explain the reading disagreement in their own words;
3. distinguish strings, lists, dictionaries, integers, Booleans and SDK response objects in the worked trace;
4. explain list positions, dictionary keys, object attributes and string methods using the two model calls;
5. use the validation diagnostic to bound a sociological claim.

## Lecture argument

An LLM becomes a research technology only when its input, transformation, output, and validation record are visible. Capability maps show where models enter research; disciplinary evidence asks what becomes easier, what becomes hidden, and who bears the checking work.

## Computational trace

Students store one trust statement and scoring instruction as strings, build one message list and send the identical request through OpenRouter and Ollama. Once both calls have run, the actual request and return objects introduce strings, lists, dictionaries, indexing, SDK attributes, string methods, integers and Booleans. Students then save both runs as a list of research-record dictionaries. Every code block is read as **input → Python type → operation → output → research meaning**.

## Weekly completion task

Run both calls and submit a narrated screen recording explaining every string, message, route and return. Explain which computation occurs remotely and locally and why either score is only a proposed measurement. Upload it through the [recording guide and Box folder](https://cjbarrie.github.io/GenAI_Soc2026/recording-and-submission.html) by 5:00 p.m. Eastern on the Tuesday before the next class.

## Validation focus

A persuasive answer is copied into an analysis while the model, settings, prompt, raw response, and validation decision remain unknown.
